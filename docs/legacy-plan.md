# Free Markdown Editor 개발 계획

## 1. 프로젝트 개요

Typora처럼 **마크다운 문법과 렌더링 결과를 한 화면에서 자연스럽게 편집**할 수 있는 무료 데스크톱 마크다운 에디터를 만든다.

- 가칭: `Free Markdown Editor`
- 대상 플랫폼: Windows 우선, 이후 macOS/Linux 확장
- 핵심 가치: 빠른 실행, 로컬 파일 중심, 깔끔한 글쓰기 경험, 무료·오픈소스
- 기본 원칙: 계정과 서버 없이도 모든 핵심 기능이 동작해야 한다.

## 2. 목표와 비목표

### 목표

1. `.md` 파일을 열고 편집하고 안전하게 저장할 수 있다.
2. 별도의 미리보기 창 없이 편집 중인 문서가 즉시 스타일링된다.
3. 제목, 목록, 인용문, 코드 블록, 표, 링크, 이미지 등 자주 쓰는 Markdown/GFM 문법을 지원한다.
4. 자동 저장, 충돌 감지, 복구 기능으로 작성 중인 내용을 잃지 않게 한다.
5. 키보드 중심으로 빠르게 사용할 수 있으며 라이트/다크 테마를 제공한다.
6. 설치 파일을 만들어 일반 Windows 앱처럼 배포할 수 있다.

### 초기 버전의 비목표

- 클라우드 동기화 및 사용자 계정
- 실시간 공동 편집
- 모바일 앱
- 플러그인 마켓플레이스
- 완전한 워드프로세서 기능
- 모든 Markdown 변형의 동시 지원

## 3. 제안 기술 스택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 데스크톱 셸 | Tauri 2 | 웹 프런트엔드를 활용하면서 비교적 작고 빠른 데스크톱 앱을 만들기 좋다. |
| 프런트엔드 | React + TypeScript + Vite | 생태계가 크고 편집기 상태와 UI를 구성하기 편하다. |
| 편집기 엔진 | Milkdown (`@milkdown/kit`) | ProseMirror와 Remark 기반의 WYSIWYG Markdown 프레임워크로 목표 경험에 가깝다. |
| Markdown 규격 | CommonMark + GFM | 일반 문법에 더해 표, 작업 목록, 취소선 등 실용 기능을 제공한다. |
| 상태 관리 | Zustand 또는 가벼운 React store | 열린 문서, 설정, UI 상태만 단순하게 관리한다. |
| 로컬 저장 | Tauri 파일 시스템/다이얼로그 API | OS 파일 선택기와 실제 `.md` 파일 읽기·쓰기를 담당한다. |
| 설정 저장 | Tauri Store 또는 로컬 설정 파일 | 테마, 글꼴, 최근 파일 등의 사용자 설정을 보존한다. |
| 테스트 | Vitest + Testing Library + Playwright | 문서 변환 단위 테스트, UI 테스트, 주요 사용자 흐름 테스트를 나눈다. |
| 패키지 관리 | pnpm | 빠르고 디스크 사용량이 적으며 의존성 관리가 명확하다. |

> 편집기 프로토타입에서 Milkdown의 Markdown 왕복 변환 품질을 먼저 검증한다. 원문 보존이 기대에 미치지 못하면 CodeMirror 6 기반 소스 모드를 기본으로 두고, 블록 단위 인라인 렌더링을 추가하는 대안을 검토한다.

## 4. 핵심 사용자 경험

### 편집 화면

- 중앙에는 여백이 넉넉한 단일 문서 편집 영역을 둔다.
- 커서가 있는 블록은 Markdown 문법 기호를 보여주고, 나머지 블록은 렌더링된 형태로 보이는 경험을 지향한다.
- 상단 UI는 최소화하고 파일명, 저장 상태, 메뉴 정도만 표시한다.
- 서식 도구는 선택 영역 근처의 작은 툴바와 명령 팔레트로 제공한다.
- `Ctrl+P` 빠른 파일 열기, `Ctrl+Shift+P` 명령 팔레트 등 익숙한 단축키를 지원한다.

### 파일 동작

- 새 문서, 열기, 저장, 다른 이름으로 저장
- 최근 문서 목록
- OS에서 `.md` 파일을 앱으로 열기
- 앱 밖에서 파일이 바뀌었을 때 변경 감지 및 선택적 다시 불러오기
- 저장되지 않은 변경이 있을 때 종료 확인
- 자동 저장은 기본 활성화하되 설정에서 끌 수 있게 한다.

### Markdown 지원 범위

- 제목, 문단, 굵게, 기울임, 취소선
- 순서/비순서 목록, 작업 목록
- 인용문, 구분선, 링크
- 인라인 코드, 코드 블록, 언어별 구문 강조
- 표
- 로컬/원격 이미지
- 이모지와 자동 링크는 후순위
- 수식, 각주, Mermaid는 확장 기능 단계에서 추가

## 5. 화면 구성

```text
┌────────────────────────────────────────────────────────────┐
│ 메뉴    document.md                         저장됨   설정 │
├───────────────┬────────────────────────────────────────────┤
│ 파일 탐색기   │                                            │
│ (접기 가능)   │             문서 편집 영역                 │
│               │                                            │
│ recent/       │       # 제목                               │
│  note.md      │       자연스럽게 렌더링되는 본문…          │
│  todo.md      │                                            │
├───────────────┴────────────────────────────────────────────┤
│ 단어 수 · 글자 수 · 현재 줄 · Markdown                    │
└────────────────────────────────────────────────────────────┘
```

MVP에서는 파일 탐색기를 생략하고 단일 문서 편집에 집중해도 된다. 폴더 작업공간은 두 번째 단계에서 추가한다.

## 6. 데이터와 상태 설계

문서 한 개의 최소 상태:

```ts
type DocumentState = {
  id: string;
  path: string | null;
  title: string;
  markdown: string;
  lastSavedMarkdown: string;
  encoding: 'utf-8';
  lineEnding: 'lf' | 'crlf';
  dirty: boolean;
  externalModifiedAt: number | null;
};
```

저장 흐름:

1. 편집 이벤트가 발생하면 메모리 상태와 `dirty` 값을 갱신한다.
2. 일정 시간 입력이 멈추면 자동 저장을 요청한다.
3. 디스크 파일의 수정 시각이 예상과 다르면 덮어쓰지 않고 충돌 안내를 표시한다.
4. 임시 복구본을 별도 앱 데이터 폴더에 기록한다.
5. 정상 저장 후 `lastSavedMarkdown`, 수정 시각, `dirty` 값을 갱신한다.

## 8. 단계별 구현 계획

### Phase 0 — 기술 검증

- [ ] Tauri + React + TypeScript 최소 앱 생성
- [ ] Milkdown으로 Markdown 입력 및 렌더링 구현
- [ ] Markdown → 편집기 → Markdown 왕복 변환 테스트
- [ ] 표, 작업 목록, 코드 블록, 이미지 샘플 검증
- [ ] 한글 입력기(IME), 실행 취소/다시 실행, 복사/붙여넣기 검증
- [ ] 1MB 이상 문서에서 입력 반응성과 시작 시간 측정

**완료 기준:** 한글 입력이 안정적이고, 대표 문법 샘플이 의미 손실 없이 저장된다.

- [ ] 새 문서, 파일 열기, 저장, 다른 이름으로 저장

## 9. 품질 및 테스트 전략

### 반드시 자동화할 항목

- Markdown 문법별 입력/출력 왕복 테스트
- CRLF/LF와 UTF-8 한글 파일 보존
- 저장하지 않은 문서의 종료 방지
- 자동 저장 중 오류가 발생했을 때 원본 보호
- 외부 파일 변경 충돌 감지
- 이미지 상대 경로 생성
- 대용량 문서에서 편집 지연이 허용 범위인지 확인

### 수동 검증 체크리스트

- 한글 조합 중 글자가 중복되거나 커서가 튀지 않는가?
- 붙여넣은 텍스트와 Markdown이 예상대로 유지되는가?
- 표와 목록에서 Enter/Tab/Backspace 동작이 자연스러운가?
- 실행 취소가 파일 열기나 자동 저장 경계를 넘어 이상하게 동작하지 않는가?
- 다크 테마에서 코드, 링크, 선택 영역의 대비가 충분한가?
- 강제 종료 후 최신 내용이 복구되는가?

## 10. 주요 위험과 대응

| 위험 | 대응 |
| --- | --- |
| WYSIWYG 변환 과정에서 원문 포맷이 달라짐 | 왕복 변환 fixture를 먼저 만들고, 원문 보존이 필요한 문법은 소스 모드로 편집한다. |
| 한글 IME와 ProseMirror 조합 문제 | Phase 0에서 Windows 한글 입력을 최우선으로 검증하고 회귀 테스트 시나리오를 둔다. |
| 자동 저장이 외부 변경을 덮어씀 | 저장 전 수정 시각/내용 해시를 확인하고 충돌 선택 UI를 제공한다. |
| 이미지 경로가 다른 PC에서 깨짐 | 문서 옆 전용 assets 폴더와 상대 경로를 기본 정책으로 삼는다. |
| 기능 확장으로 앱이 복잡해짐 | MVP 범위를 고정하고 편집 기능은 플러그인 단위로 분리한다. |
| 운영체제별 파일 동작 차이 | 파일 서비스 계층을 분리하고 Windows를 먼저 안정화한 뒤 다른 OS를 검증한다. |

## 11. MVP 완료 정의

다음 조건을 모두 만족하면 첫 번째 공개 가능한 버전으로 본다.

- Windows에서 설치와 실행이 가능하다.
- `.md` 파일 연결 또는 파일 열기로 문서를 불러올 수 있다.
- 대표 CommonMark/GFM 문서를 편집하고 다시 열었을 때 내용 의미가 유지된다.
- 한글 입력, 복사/붙여넣기, 실행 취소/다시 실행이 안정적이다.
- 수동 저장, 자동 저장, 종료 전 확인, 복구 기능이 동작한다.
- 라이트/다크 테마와 기본 단축키가 동작한다.
- 치명적 데이터 손실 시나리오에 대한 테스트가 통과한다.
- README에 설치, 실행, 개발 방법과 알려진 제한사항이 기록되어 있다.

## 12. 첫 개발 스프린트 제안

1. 프로젝트 스캐폴딩과 개발 환경 구성
2. 대표 Markdown fixture 문서 작성
3. Milkdown 기본 편집기와 테마 구현
4. Tauri 파일 열기/저장 연결
5. dirty 상태와 창 제목의 저장 상태 표시
6. 한글 IME 및 Markdown 왕복 변환 검증
7. 결과를 바탕으로 MVP 기술 선택 확정

첫 스프린트의 최우선 산출물은 화려한 UI가 아니라 **실제 `.md` 파일을 열어 한글로 편집하고, 내용 손실 없이 저장하는 작동 가능한 세로 조각(vertical slice)**이다.
